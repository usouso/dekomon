# 独立レビュー手順
1. [共通標準](GAME-DEVELOPMENT-STANDARD.md)を読み、担当・対象commit・制作中/予約済み作業とLOCKを確認する。
2. 制作担当の作業ツリーを動かさず、隔離した対象commitで差分を検査する。コードレビュー、単体テスト、自動検査、実操作を分けて記録する。
3. 必要な既存依存だけを使用する。検証サーバーはloopbackに限定し、既存ポートを奪わない。環境変更が必要なら、その工程を停止して具体的に記す。
4. 起動した実体とcommitを対応させる。公開URLだけで新headを起動したと決めない。ユーザーのセーブと進行中タブを保護する。
5. タイトルから結果まで通常入力で通し、画面寸法・seed・入力・console/pageerror・画面証拠を保存する。自動モードやdebug直行は別結果にする。
6. 各repoの検証手順に従い、単体テストと自動検査を実行して判定範囲を確かめる。コマンドの記載を実施記録にせず、実際の終了コードと証拠を残す。
7. [引継ぎ書式](HANDOFF-TEMPLATE.md)で制作担当へ渡し、受領を確認する。修正commitを別担当が同じ条件で再テストする。台帳の場所は各repoの入口で指定する。
8. 作成した検証サーバーとタブだけを閉じる。公開・merge等は別の承認工程として扱う。
